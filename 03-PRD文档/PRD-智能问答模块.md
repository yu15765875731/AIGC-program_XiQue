## 2. 背景与目标

### 2.1 背景
知识库有了，但**用户不会用**：有人怕不准不敢信，有人找不到入口，有人问了问题答案里没来源就不敢用。核心矛盾：LLM 能力强但企业用户不信"黑盒"答案，需要**透明度 + 可验证**。

### 2.2 目标

| 指标 | V1.0 目标 |
|------|-----------|
| 首次问答转化率 | 注册 7 天内完成首次问答 > 60% |
| 问答满意度（👍 比例） | > 80% |
| 平均响应时间 | P95 < 3s |
| 答案可溯源率 | 100%（每条答案必须带引用） |

## 3. 用户画像 & 使用场景

### 3.1 核心用户故事

| # | 角色 | 故事 | 验收标准 |
|---|------|------|----------|
| Q1 | 新员工 | 作为新员工，我想一句话问"年假怎么算"，得到准确答案 | 答案带年假制度文档引用 + 一键跳转 |
| Q2 | 客服 | 作为客服，我想帮客户查"退货运费谁承担"，答案要能直接发给客户 | 答案格式适合复制粘贴，带关键条款原文 |
| Q3 | 管理者 | 作为管理者，我想知道"上周大家都在问什么"，帮我优化知识库 | 后台有 Top 问题列表 + 低满意度问题告警 |
| Q4 | 合规 | 作为合规，我想知道"这个答案引用了哪份文档哪几行" | 每条答案的引用精确到片段 + 页码 + 可预览 |

### 3.2 多轮上下文场景

```
用户：年终奖怎么算？          → 系统回答年终奖规则
用户：那试用期的呢？           → 系统理解上下文是"试用期年终奖"，而非重新检索"试用期"
用户：和转正的有什么区别？    → 系统对比两者条款，输出对照表
```

## 4. 功能需求

### 4.1 对话界面

| 功能 | 描述 | 优先级 | 决策依据 |
|------|------|--------|----------|
| 单轮提问 | 输入框 + 回车发送 | P0 | 核心入口 |
| 多轮上下文 | 自动保持会话，理解代词/省略 | P0 | 用户真实使用习惯不是单轮 |
| 历史对话 | 侧边栏展示 + 点击恢复 | P0 | 避免每次都重新输入长问题 |
| 知识库选择 | 可选择"全部知识库"或指定 1-N 个 | P0 | 跨库 vs 单库检索效果不同 |
| 快速提问建议 | 空输入时展示 Top 5 热门问题 | P1 | 降低首次使用门槛 |
| 语音输入 | 浏览器 Web Speech API | P2 | 提升移动端体验 |

**空状态引导设计：**
```
┌──────────────────────────────┐
│  👋 你好，我可以帮你回答       │
│     公司内部的任何问题         │
│                              │
│  💡 试试这些：                 │
│  ┌────────────────────┐      │
│  │ 年假怎么算？       │      │
│  ├────────────────────┤      │
│  │ 差旅报销流程？     │      │
│  ├────────────────────┤      │
│  │ 试用期工资怎么发？ │      │
│  └────────────────────┘      │
│                              │
│  [选择知识库 ▼]  [输入问题…]  │
└──────────────────────────────┘
```

### 4.2 答案展示

| 元素 | 描述 | 优先级 | 设计理由 |
|------|------|--------|----------|
| 正文回答 | 结构化 Markdown 渲染 | P0 | 清晰易读 |
| 来源卡片 | 每个引用片段一个卡片：文档名 + 页码 + 片段预览 | P0 | **企业级底线：答案可验证** |
| 引用跳转 | 点击卡片 → 弹窗预览原文片段 | P0 | 快速验证 |
| 👍👎 反馈 | 每条回答底部 | P0 | 收集信号用于 Rerank 优化 |
| 复制按钮 | 一键复制正文 | P1 | 客服高频需求 |
| 重新生成 | 不满意可换一种表述 | P1 | 不是所有问题都一次答对 |

**答案卡片布局：**
```
┌──────────────────────────────────────────┐
│  差旅报销分为 3 步：                      │
│  1. 填写差旅报销申请表                    │
│  2. 部门负责人审批                        │
│  3. 财务审核并打款                        │
│  ...                                     │
│                                          │
│  ── 来源 ──                              │
│  ┌─────────────────────────────────────┐ │
│  │ 📄 差旅管理制度.pdf  P12-14         │ │
│  │ "差旅报销流程如下：..."              │ │
│  └─────────────────────────────────────┘ │
│                                          │
│  👍  👎  📋复制  🔄重新生成               │
└──────────────────────────────────────────┘
```

### 4.3 问答模式

| 模式 | 适用场景 | 配置差异 | 优先级 |
|------|----------|----------|--------|
| 快速 | 日常提问 | Rerank Top 3 / LLM 短回答 | P0 |
| 深度 | 写报告、调研 | Rerank Top 5 / 长回答 / 更多上下文 | P1 |
| 专业 | 合规审查、合同 | 显式引用所有片段 / 允许引用不足时说"我不确定" | P1 |

### 4.4 反馈学习闭环（3 年经验核心！）

```
用户 👍 → 记录 (question, chunk_ids, 正向反馈)
用户 👎 → 弹窗收集原因（多选）
         ├── 答案不正确（最常见）
         ├── 答案不完整
         ├── 格式不好读
         └── 引用不对
         
         → 记录 (question, chunk_ids, 原因)
         → 后台每天离线分析 👎 原因
         → 高频问题 → 人工标注正确答案 → 进入 FAQ 增强
         → 检索效果差的知识库 → 建议调整切片参数
```

**这个闭环体现的经验思维：**
- 不只是收集数据，要**把反馈变成可操作的优化**
- 离线批量分析 vs 实时处理（降低成本 + 保证稳定性）
- 有问题先归因（检索问题 vs 生成问题 vs 知识库内容问题），不要只调 LLM prompt

## 5. 非功能性需求

| 类型 | 指标 | 说明 |
|------|------|------|
| 性能 | P95 响应时间 | < 3s（不含 LLM 生成） |
| 性能 | LLM Token | 单次问答 ≤ 4K（控制成本） |
| 安全 | 敏感内容过滤 | 答案中不出现未授权文档 |
| 可观测 | 全链路日志 | 每个 QA 记录：Query / 检索结果 / Rerank 结果 / LLM 输入输出 / 耗时 |

## 6. 核心交互流程

```
用户输入问题
    │
    ├── 空输入 → 显示热门问题建议 → 用户点击
    │
    ▼
系统处理 Query 改写
    │
    ├── 改写失败 → 用原始问题检索（降级）
    │
    ▼
混合检索（向量 + 关键词）
    │
    ├── 0 结果 → 提示"知识库中未找到相关内容" + 建议检查知识库或换关键词
    │
    ▼
Rerank 重排
    │
    ├── Top 片段分数 < 阈值 → 提示"信心不足，以下答案可能不准确"
    │
    ▼
Prompt 组装 → LLM 生成
    │
    ├── LLM 超时 → 降级：直接返回检索片段原文
    ├── LLM 返回无引用 → 答案校验不通过 → 提示"生成失败，请重试"
    │
    ▼
返回答案 + 来源卡片
    │
    ▼
用户反馈 👍/👎 → 进入反馈学习闭环
```

## 7. 验收标准

```
[ ] 输入"年假怎么算"，3s 内返回答案 + 引用
[ ] 多轮对话中，问"那试用期的呢？"，系统正确理解上下文
[ ] 答案中每个来源都可点击预览原文
[ ] 完全不相关的问题，系统诚实回答"未找到"，而不是瞎编
[ ] 用户 👎 后，后台能看到反馈记录和原因
[ ] 历史对话可恢复，上下文保持正确
```

## 8. 依赖与风险

| 依赖 | 负责方 | 风险 | 预案 |
|------|--------|------|------|
| Rerank 模型（BGE-Reranker） | 算法组 | 重排耗时 | 缓存 Top K 片段，只重排 Top 20 |
| LLM API（GPT-4o-mini / DeepSeek） | 外部 | 生成质量不稳定 | Prompt 中强约束：必须引用、格式检查 |
| 向量库检索 | 运维组 | 延迟波动 | 高频查询结果 + 检索片段缓存 |
