## 2. 背景与目标

### 2.1 背景
企业内部知识散落在各种载体上（本地文件夹、网盘、邮件、IM），新员工入职翻文档要花 2 周以上才能独立，客服每天重复回答相同问题 50+ 次。**核心原因是：知识没有被结构化索引，只能靠"人传人"。**

### 2.2 目标
| 指标 | 当前 | V1.0 目标 | 测量方式 |
|------|------|-----------|----------|
| 知识获取耗时 | 15 分钟/次 | < 1 分钟/次 | 用户自测 |
| 新员工上手周期 | 14 天 | < 7 天 | 入职跟踪 |
| 客服重复回答率 | 60% | < 40% | 客服录音抽样 |

## 3. 用户画像 & 使用场景

### 3.1 核心用户故事

| # | 角色 | 故事 | 验收标准 |
|---|------|------|----------|
| U1 | IT 管理员 | 作为 IT，我希望能批量上传一个文件夹里的 50+ 份文档，而不是一个一个传 | 上传文件夹后 5 分钟内全部处理完成 |
| U2 | HR | 作为 HR，我希望修改了员工手册后，旧的问答结果不会继续出现 | 文档更新后，新问题立即检索到新版本 |
| U3 | 新员工 | 作为新员工，我希望搜索"入职"能找到所有相关文档 | 搜索结果按相关度排序，支持按知识库筛选 |
| U4 | 老板 | 作为老板，我希望敏感文档（合同）不被问答搜索到 | 可设置知识库为"不参与问答"，仅管理员可见 |

### 3.2 非目标（Out of Scope）
- 多人实时协作编辑文档
- 视频/音频内容处理
- 文档内容的 AI 生成和自动更新（V1.0 不做）

## 4. 范围界定

**本期 In Scope：**
- 知识库 CRUD（创建 / 删除 / 归档）
- 手动上传文档（PDF / Word / Markdown / TXT / 表格）
- 文件夹批量导入
- URL 抓取（单页面）
- 文档自动切片 + 向量化
- 处理进度查看
- 基础检索策略配置（默认 / 语义优先 / 关键词优先）

**本期 Out of Scope：**
- 企业系统 API 自动同步
- 图片 OCR
- 增量更新自动检测
- 多语言内容支持

## 5. 功能需求

### 5.1 知识库 CRUD

| 功能 | 描述 | 优先级 | 决策依据 |
|------|------|--------|----------|
| 创建知识库 | 输入名称 + 描述 + 选择 embedding 模型 | P0 | 模型选了就不能改，所以创建时必须选好；给 2 个选项：通用模型（快）/ 专业模型（准） |
| 删除知识库 | 二次确认 + 30 天可恢复 | P0 | 防误删，企业数据宝贵 |
| 归档知识库 | 不删但不参与检索 | P1 | 合规需求：老制度要留档但不能被问到 |

**交互说明：**
- 创建空状态 → 引导去上传文档
- 上传中 → 显示进度条 + 当前文件名
- 处理失败 → 红色标记 + 可点击查看失败原因

### 5.2 文档导入

| 导入方式 | 支持格式 | 单文件上限 | 优先级 |
|----------|----------|------------|--------|
| 手动上传 | PDF / DOCX / MD / TXT / CSV / XLSX | 50 MB | P0 |
| 文件夹批量 | 同上 | 100 个文件 | P0 |
| URL 抓取 | HTTPS 页面 | 单页 | P1 |
| API 同步 | 按需配置 | - | P2 |

**异常处理矩阵：**

| 异常 | 处理 | 用户提示 |
|------|------|----------|
| 文件格式不支持 | 跳过该文件 | "不支持 .rar，仅支持 PDF/DOCX/MD/TXT" |
| 文件 > 50MB | 拦截上传 | "文件过大（63MB），请拆分后上传" |
| 文件内容为空 | 标记为失败 | "未识别到有效文本内容" |
| 网络中断 | 断点续传 | "网络中断，已上传 3/8 文件，恢复后继续" |
| 内容 hash 重复 | 跳过 + 提示 | "该文档已存在，是否覆盖？" |

### 5.3 文档处理 Pipeline

```
原始文件 → 格式解析 → 文本提取 → 结构化识别
                                      │
                                      ▼
                              智能切片（分块）
                              ├── 按标题段落切（优先）
                              ├── 代码块保留完整
                              └── 超长段落按字数切（500 字/块，200 重叠）
                                      │
                                      ▼
                              向量化（Embedding API）
                                      │
                                      ▼
                              写入向量索引
```

**切片参数可配置（P1）：**
- 默认 500 字/块，200 重叠
- 可自定义：300-1000 字，重叠 0-300 字

### 5.4 检索策略配置

| 策略 | 适用场景 | 实现 |
|------|----------|------|
| 平衡（默认） | 通用问答 | 向量 60% + 关键词 40% 混合 |
| 语义优先 | 自然语言、模糊问题 | 向量 80% + 关键词 20% |
| 关键词优先 | 查条款、查数字、查代码 | 向量 30% + 关键词 70% |
| 高精度 | 合规审查、合同问答 | 只取 Rerank Top 3 片段 |
| 高召回 | 调研、写报告 | 取 Top 10 片段 + 生成时要求更多上下文 |

## 7. 数据实体（节选）

```
知识库 KnowledgeBase
├── id (uuid)
├── name (varchar 100)
├── description (text)
├── embedding_model (enum: BGE-M3 / text-embedding-3-small)
├── retrieval_strategy (enum: balanced / semantic / keyword)
├── member_count (int)
├── is_active (bool) — 归档 = false
├── created_by (uuid → User.id)
└── created_at / updated_at (datetime)

文档 Document
├── id (uuid)
├── kb_id (uuid → KnowledgeBase.id)
├── source_type (enum: upload / folder / url)
├── file_name (varchar 255)
├── content_hash (varchar 64 — SHA-256)
├── status (enum: pending / processing / done / failed)
├── chunk_count (int)
├── failed_reason (text — nullable)
└── uploaded_at (datetime)

片段 Chunk
├── id (uuid)
├── doc_id (uuid → Document.id)
├── chunk_index (int — 在原文档中的位置)
├── content (text — 切片后的文本)
├── embedding (vector 1024 — BGE-M3)
├── embedding_model (varchar)
└── created_at (datetime)
```

## 8. 验收标准

```
[ ] 上传单个 PDF（20 页），3 分钟内处理完成，状态变为"已完成"
[ ] 上传文件夹（10 个文件），进度条实时显示当前文件
[ ] 搜索关键词，结果能命中原文且片段位置正确
[ ] 不支持的文件格式被拦截并提示
[ ] 文档更新后，旧版本片段被向量库标记为失效，不会被检索到
[ ] 删除知识库后，30 天内可恢复
```

## 9. 依赖与风险

| 依赖 | 负责方 | 风险 | 预案 |
|------|--------|------|------|
| BGE-M3 向量化 API | 算法组 | API 不稳定影响处理速度 | 备用 text-embedding-3-small 作为 fallback |
| Milvus 向量库 | 运维组 | 写入延迟 | 预建索引 + 批量写入 |
| PDF 解析库 | 自研 | 扫描版 PDF 无法提取 | V1.0 不支持扫描版，明确告知用户 |
