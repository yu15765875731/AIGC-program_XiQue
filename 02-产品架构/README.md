# 产品架构

> 本文档描述产品的**分层架构、信息架构、业务流程**，面试时用来说明"你是怎么拆解一个复杂产品的"。

## 1. 分层产品架构（4 层）

```
┌─────────────────────────────────────────────────────────┐
│                     用户层（User Layer）                │
│  Web 端  │  企业微信/飞书机器人  │  API/SDK  │  管理后台 │
├─────────────────────────────────────────────────────────┤
│                     应用层（Application Layer）         │
│                                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ 知识库管理   │  │ 智能问答     │  │ Agent 工作流  │  │
│  │ 模块         │  │ 模块         │  │ 编排模块      │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ 用户/权限    │  │ 计费订阅     │  │ 分析报告     │  │
│  │ 模块         │  │ 模块         │  │ 模块         │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
├─────────────────────────────────────────────────────────┤
│                     服务层（Service Layer）             │
│                                                         │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ RAG 引擎     │  │ LLM 网关     │  │ 检索服务     │  │
│  │ （核心引擎） │  │ （统一接入） │  │ （混合检索） │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │ 文档处理     │  │ Agent        │  │ 反馈学习     │  │
│  │ Pipeline     │  │ 调度器       │  │ 服务         │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
├─────────────────────────────────────────────────────────┤
│                     数据层（Data Layer）                │
│  关系型DB │ 向量DB │ 对象存储 │ 缓存 │ 日志分析DB       │
└─────────────────────────────────────────────────────────┘
```

**每层设计思路：**

| 层 | 职责 | 设计原则 | 面试加分点 |
|----|------|----------|------------|
| 用户层 | 多端触达，适配不同使用场景 | 同一后端服务支持多前端 | 为什么要做 API/SDK？→ 被集成进企业已有系统 |
| 应用层 | 按业务域拆模块，模块低耦合高内聚 | 每个模块可独立迭代、可单独下线 | 模块边界怎么划的？→ 按用户核心任务流 |
| 服务层 | 通用能力下沉，供多模块复用 | 无业务状态、可横向扩展 | RAG 引擎为什么独立？→ 未来可换模型、换向量库 |
| 数据层 | 按数据类型选存储 | 向量/关系/文件/缓存分离 | 为什么向量数据库不用 MySQL 存？→ 查询效率差 1000x |

## 3. 核心业务流程

### 流程 A：新员工入职 → 问"公司差旅报销怎么走？"

```
用户                          系统
 │                              │
 │── 上传差旅制度PDF ──────────→│  (知识库管理)
 │                              │── 自动切片(按"差旅费管理办法"分段)
 │                              │── 向量化存储
 │                              │── 索引构建完成 ✓
 │                              │
 │── 输入问题 ─────────────────→│  (智能问答)
 │                              │── Query 改写(补全意图: 差旅报销+流程)
 │                              │── 混合检索(向量 + 关键词)
 │                              │── Rerank 重排 Top 5 片段
 │                              │── LLM 生成答案(带引用)
 │←── 返回答案 ────────────────│
 │   "差旅报销分3步:            │
 │    1. 填申请表...           │
 │    2. 部门审批...           │
 │    来源: 差旅制度.pdf P12-14 │
 │                              │
 │── 点👍反馈 ─────────────────→│── 记录正反馈(强化该片段权重)
```

### 流程 B：客服 Agent 自动应答

```
用户在企业微信提问
      │
      ▼
飞书/企业微信机器人接入 → 触发 Agent 工作流
      │
      ▼
Agent 调度器 ──→ 判断意图(FAQ? 转人工? 需要查知识库?)
      │
      ├──→ 查知识库 → 返回答案
      ├──→ 转人工 → 推送到客服工作台
      └──→ 触发工作流(如"退货运费谁承担") → 拉取订单API → 生成回复
```

### 流程 C：知识库自动更新

```
每天凌晨
      │
      ▼
定时任务 ──→ 扫描关联文档源
               ├── 企业网盘(OneDrive/Google Drive)
               └── 企业 API(HR 系统/CRM)
      │
      ▼
增量检测(对比文件 hash) ──→ 仅处理变更的文件
      │
      ▼
重新切片 + 向量化 ──→ 更新向量库
      │
      ▼
通知 Admin: "有 3 份文档已更新"
```

## 4. 数据流向（面试高阶加分项）

```
                    ┌──────────────┐
                    │  用户查询    │
                    └──────┬───────┘
                           ▼
                    ┌──────────────┐
                    │  Query 改写  │──┐
                    └──────┬───────┘  │
                           ▼          │
              ┌───────────────────────┤
              ▼                       ▼
       ┌──────────────┐        ┌──────────────┐
       │ 向量检索     │        │ 关键词检索   │
       └──────┬───────┘        └──────┬───────┘
              │                       │
              └───────────┬───────────┘
                          ▼
                   ┌──────────────┐
                   │ Rerank 重排   │──→ Top K 片段
                   └──────┬───────┘
                          ▼
                   ┌──────────────┐
                   │ Prompt 组装  │──→ System Prompt + 检索片段 + 用户问题
                   └──────┬───────┘
                          ▼
                   ┌──────────────┐
                   │   LLM 生成   │──→ 带引用的结构化 JSON 输出
                   └──────┬───────┘
                          ▼
                   ┌──────────────┐
                   │ 答案校验     │──→ 包含引用? 分数过阈值?
                   └──────┬───────┘
                          ▼
                   ┌──────────────┐
                   │  返回用户    │
                   └──────────────┘
```

**这个流程设计体现的 3 年经验思维：**
- 为什么要 Query 改写？→ 用户原始问题可能太碎（"报销" vs "差旅报销审批流程"），改写后检索准确率提升 20-30%
- 为什么混合检索？→ 纯向量对数字/代码/专有名词效果差，纯关键词对语义理解差，两者互补
- 为什么要 Rerank？→ 召回阶段可以宽一些（Top 50），重排阶段精准（Top 5），平衡召回率和准确率
- 为什么答案要校验？→ 防止 LLM 生成无引用的幻觉答案，这是企业级产品的底线
