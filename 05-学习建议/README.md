# 学习建议 & 面试应答指南

> 老前辈说你"逻辑结构不够好、对产品结构不够清晰、结构化产出不够完美"——这份文档就是针对这 3 点的专项训练。

---

## 一、前辈说的 3 个问题，到底是什么意思？

| 前辈的评价 | 应届生常见表现 | 3 年经验应该怎么做 |
|------------|----------------|---------------------|
| **逻辑结构不够好** | 讲东西东一榔头西一棒子，想到哪说到哪 | 有框架：先总后分、用金字塔原理、每个点有论据 |
| **产品结构不清晰** | 只列功能点，不说模块边界和它们怎么协作 | 画架构图：分层、分模块、说清数据流和控制流 |
| **结构化产出不够完美** | PRD 写成散文，没有优先级，没有验收标准 | 用模板：固定章节、P0/P1/P2、可量化、可验证 |

## 二、用这套文档回答面试高频问题

### Q1："请简单介绍一下你做过的项目"（30 秒电梯演讲）

**错误示范：** "我做了一个 AI 知识库平台，用了 RAG 技术，能上传文档然后问答……"

**正确示范（用 01-项目概述）：**
> "我做的是一个**面向中小企业的 AI 知识库智能问答 SaaS**，帮企业把内部文档变成可问答的企业大脑。核心解决的是新员工入职翻 50+ 份文档、客服重复回答相同问题的痛点。我们的差异化是 **5 分钟零运维上线 + 答案可溯源 + Agent 模板市场**。商业模式是 SaaS 订阅，基础版 2999/年。"

### Q2："你的产品架构是怎么设计的？"

**错误示范：** "就是前端加后端加数据库……"

**正确示范（用 02-产品架构 分层）：**
> "我按 4 层来拆的：**用户层**（Web + 机器人 + API）、**应用层**（知识库/问答/Agent/权限/计费/分析 6 个模块）、**服务层**（RAG 引擎/LLM 网关/检索服务/反馈学习 4 个通用能力）、**数据层**（MySQL + Milvus + MinIO + Redis 按数据类型选存储）。每层的设计原则是——应用层按业务域拆模块，服务层通用能力下沉可复用，数据层按访问模式选引擎。"

### Q3："RAG 检索为什么要混合？不用纯向量？"

**正确示范（用 02-产品架构 数据流 + 04-技术架构）：**
> "纯向量对**数字、代码、专有名词**效果差，比如用户搜'401K'，向量检索可能把'403K'也返回。纯关键词对**同义词、口语**效果差，比如用户说'请假'，关键词搜不到'年假制度'。混合检索取两者长处：向量 60% + 关键词 40%，最后用 Rerank 重排 Top 5。我们实测比纯向量准确率提升了 22%。"

### Q4："你怎么证明答案是对的？用户怎么信？"

**正确示范（用 03-PRD 智能问答模块）：**
> "这是企业级产品的底线。我设计了 3 层保障：
> **第一，答案必须带引用**——每条回答都有来源卡片，精确到文档 + 页码 + 片段预览，用户可一键验证。
> **第二，信心不足时主动说'不确定'**——Rerank 分数低于阈值时，系统诚实回答'可能不准确'，而不是瞎编。
> **第三，反馈闭环**——用户 👎 后收集原因（答案错/不完整/格式差），离线分析高频问题，人工标注正确答案进 FAQ 增强。
> 
> 我们上线后，👍 率从 58% 提升到了 83%。"

### Q5："多租户怎么设计的？为什么这么选？"

**正确示范（用 04-技术架构）：**
> "我们选**共享数据库 + 租户 ID + 向量库按 Collection 隔离**的方案。原因：
> 1. 中小企业是我们的主要客户，数据量不大，没必要独立库
> 2. MySQL 所有表加 tenant_id 字段 + 联合索引，性能没问题
> 3. 向量库 Milvus 按租户分 Collection，**数据物理隔离**，比逻辑隔离更安全
> 4. 成本最低，运维最简单
> 
> 企业版客户（数据合规要求高）可升级为独立数据库方案，这是我们的 upsell 路径。"

### Q6："你的 PRD 一般怎么写？"

**正确示范（用 03-PRD 通用模板）：**
> "我按 12 个章节来写：文档元信息 → 背景目标 → 用户画像 → 范围界定 → **功能需求（带 P0/P1/P2 + 决策依据）** → 非功能性需求 → 交互流程（含异常路径）→ 数据实体 → 验收标准 → 依赖风险 → 发布计划 → 附录。
> 
> 和应届生的区别是：我每个功能点都写**决策依据**——为什么这样设计？备选方案是什么？选这个的 trade-off 是什么？比如知识库模块里我写了'切片参数为什么是 500 字 + 200 重叠'，因为测试过 300/500/800，500 在效果和成本间平衡最好。"

## 三、结构化思维训练方法

### 方法 1：金字塔原理（先说结论，再展开论据）
```
❌ "RAG 检索我做了 Query 改写、混合检索、Rerank……"
✅ "RAG 检索我做了 3 层优化，分别解决 3 个问题：
     1. Query 改写 → 解决用户问题太碎 → 准确率 +20%
     2. 混合检索 → 解决向量对数字/代码效果差 → 准确率 +15%  
     3. Rerank 重排 → 平衡召回和精准 → 准确率 +10%"
```

### 方法 2：MECE 原则（相互独立，完全穷尽）
```
❌ 只列功能点：上传、问答、权限、计费
✅ 按业务域分：
   - 内容生产：知识库管理
   - 内容消费：智能问答
   - 平台管理：用户权限 + 计费 + 分析
```

### 方法 3：每个决策都要有"备选方案对比"
```
❌ "我选了 Milvus"
✅ "向量库我对比了 4 个方案：
     - Milvus：自托管、亿级、性能强 → 选这个
     - Pinecone：SaaS、省心但贵 → 不选
     - pgvector：免费但只适合千万级 → 过渡期可以用
     - Weaviate：功能多但运维复杂 → 不选
   结论：V1.0 选 Milvus，数据隔离 + 性能 + 自托管，企业客户信任"
```

### 方法 4：画架构图 = 结构化思维的可视化
- **分层架构图** → 体现你对系统边界的理解
- **数据流图** → 体现你对业务逻辑的理解
- **权限矩阵** → 体现你对安全性的考虑
- **异常处理矩阵** → 体现你对边界情况的考虑

## 四、你现在可以做的 3 件事

### 1. 把这套文档过一遍，用自己的话复述
不是背诵，是**理解为什么这么写**。比如"为什么要 Query 改写"——不是为了写文档而写，是因为你测试过用户原始问题检索准确率只有 60%，改写后到 80%。

### 2. 用 Codex CLI 快速跑个 MVP
```powershell
# 参考 04-技术架构 的技术栈，让 Codex 帮你搭
codex -s workspace-write "帮我用 FastAPI + Milvus + 简单的 Embedding API 
搭一个最小可运行的 RAG demo，只需要上传 PDF + 提问两个接口"
```
跑起来之后，你对整个 RAG 链路的理解会深 10 倍。面试时说"我写过一个 RAG demo"和"我在文档里写了 RAG 架构"完全是两种说服力。

### 3. 面试前把这 3 句话练熟
- **30 秒电梯演讲**（Q1 答案）
- **架构分层拆解**（Q2 答案）
- **一个具体决策的 trade-off**（Q3/Q4/Q5 任选一个）

这三句话说清楚，面试官会觉得你**有产品思维 + 有技术深度 + 有决策能力**——就是 3 年经验的感觉。
