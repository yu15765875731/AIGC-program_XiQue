## 1. 三条路径怎么选

| | 路径 A：Dify 云端 | 路径 B：Docker 自建 Dify | 路径 C：本机 Python V0 |
|---|---|---|---|
| **安装成本** | 零，注册即用 | 装 Docker Desktop（~2GB，需重启） | **零** |
| **上手时间** | 20 分钟 | 1~2 小时 | **5 分钟** |
| **可视化编排** | ✅ 拖拽 | ✅ 拖拽 | ❌ 命令行 |
| **能跑评测吗** | 要手动导出 | 要手动导出 | ✅ **自带评测脚本** |
| **面试说服力** | 中（像「用了个工具」） | 中高 | **高（代码 + 评测集 + 报告全是你自己做的）** |
| **适合** | 快速看效果 / 做界面截图 | 想要完整产品形态 | ⭐ **PM 能力展示（推荐主线）** |
| **数据隐私** | 文档要传给第三方 | 全本地 | 全本地 |

### 我的建议：**A + C 组合**

- **路径 C 做主线**：它自带评测集和评测报告，这是你简历里最值钱的部分
- **路径 A 做辅助**：顺便在 Dify 上搭一个漂亮的界面，截图放进 GitHub，面试时演示用

> ⚠️ 别一上来就冲路径 B。装 Docker 会吃掉你一整个晚上，而且装完你还是在做「配置」，没在做「产品决策」。

### 演示时最好用的两个例子

```powershell
# ① 能答对的（展示引用 + 置信度）
.\.venv\Scripts\python.exe ask.py -q "实验室安全考试的合格线是多少分"
#   → 置信度 0.97，返回「80 分」+ 来源《实验室安全守则》

# ② 该拒答的（展示「敢说不知道」）
.\.venv\Scripts\python.exe ask.py -q "学校的股票代码是多少"
#   → 「未找到可靠依据」，置信度 0.06

# ③ ⭐ 一个真实的失败案例（面试时最值钱）
.\.venv\Scripts\python.exe ask.py -q "请假两天找谁审批"
#   → 被误拒！因为文档写的是「2 至 3 天」，用户说的是「两天」—— 这就是「词汇鸿沟」
```

**第 ③ 个例子请务必留着。** 面试时主动展示一个失败案例并讲清根因，比只报喜有说服力得多。
详见 [07-评测体系/README.md](../07-评测体系/README.md) 第 5 节结论 4。

## 2. 路径 C：本机 Python V0（已跑通，推荐）

代码在 [local_rag/](local_rag/)，**我已在你这台机器上实际跑通并产出了评测报告**。

### 30 秒启动

```powershell
cd 08-V0原型\local_rag

# 1) 建索引（读 data\docs 下的文档 → 切片 → 落盘）
.\.venv\Scripts\python.exe ingest.py

# 2) 问一句试试
.\.venv\Scripts\python.exe ask.py -q "实验室安全考试的合格线是多少分" --show-chunks

# 3) 跑评测，拿到你自己的真实数字
.\.venv\Scripts\python.exe evaluate.py --set ../../07-评测体系/eval_set_demo.csv --tag v0
```

> 虚拟环境 `.venv` 我已经建好，`jieba` 也装好了（`requirements.txt` 里声明）。
> 首次运行请先看 [local_rag/README.md](local_rag/README.md)。

### 实测基线（真跑出来的，不是编的）

| 配置 | 答案正确率 | 要点覆盖率 | 拒答准确率 | 幻觉率 |
|------|-----------|-----------|-----------|--------|
| 不设拒答阈值 | 93.8% | 0.938 | 0% | **100%** |
| **V0 基线：BM25 Top-1 + 阈值** | **86.2%** | 0.863 | **90.0%** | **10.0%** |
| V0.5：Top-3 拼接 | 87.5% | 0.875 | 90.0% | 10.0% |
| 换成 jieba 分词 | 68.8% | 0.688 | 90.0% | 10.0% |

**这四个数字就是你的第一份作品。** 详细解读见 [07-评测体系/README.md](../07-评测体系/README.md) 第 5 节。

### 没配 API Key 也能干活

默认走「抽取式基线」（直接把检索到的原文当答案）。这**不是缺陷，是设计**：

- 它让你**零成本**先把「检索」这一环测清楚
- 加上 `--answer-k 3` 就能做上下文对比实验
- 配了 Key 之后自动升级成 LLM 生成，再跑一次评测就能看到提升幅度

想升级：把 [local_rag/.env](local_rag/.env) 里的 `LLM_BASE_URL` / `LLM_API_KEY` 填上即可（DeepSeek 最便宜）。

## 3. 路径 A：Dify 云端（20 分钟出界面）

### 3.1 注册

1. 打开 `https://cloud.dify.ai`
2. 用邮箱注册（免费额度够你搭完整个演示）

### 3.2 建知识库

1. 顶部切到 **「知识库」** → **「创建知识库」**
2. 把 `local_rag/data/docs/` 里的 7 份 `.md` 全部拖进去
3. **分段设置**（这一步别用默认值，面试官会问你为什么这么设）：

   | 参数 | 推荐值 | 为什么 |
   |------|--------|--------|
   | 分段模式 | 自定义 | 通用模式下它按固定长度硬切，会切断「第九条…」这种语义单元 |
   | 分段标识符 | `\n\n` | 按自然段切，段落是文档的最小语义单元 |
   | 分段最大长度 | 500 | 我实测 300/500/800 后选的：500 在「语义完整」和「检索精度」之间最平衡 |
   | 分段重叠长度 | 100 | 防止答案刚好被切在边界上 |
   | 文本预处理 | 替换连续空格/换行 | 清洗掉 PDF 复制带来的排版噪音 |

4. **索引方式选「高质量」**（用 Embedding 模型做向量检索）。
   「经济」模式只做关键词，就是你 Python 版的水平——**这个对比本身就是你的实验素材**。

5. **检索设置**：

   | 参数 | 推荐值 | 理由 |
   |------|--------|------|
   | 检索方式 | **混合检索** | 向量管语义（「请假」≈「休假」），关键词管精确（「800W」「200 篇」） |
   | 权重设置 | 语义 0.6 / 关键词 0.4 | 起步值。**你得自己跑几组对比证明它最优**，别照抄 |
   | Rerank 模型 | 开启（如有） | 粗排 50 → 精排 5，平衡召回与精准 |
   | TopK | 5 | 太少漏信息，太多稀释注意力还费 Token |
   | Score 阈值 | 先 0.5，再用评测集标定 | ⭐ **别凭感觉填。这就是你 Python 版 `calibrate.py` 干的事** |

### 3.3 建应用

1. **「工作室」** → **「创建应用」** → 选 **「聊天助手」**
2. **「上下文」** 里关联刚才的知识库
3. **「编排」** 里写系统提示词（直接抄这份）：

```
你是企业知识库问答助手。

【硬约束】
1. 你的回答必须严格基于检索到的知识片段，不得编造任何事实。
2. 如果知识片段不足以回答，必须明确回答"未在知识库中找到可靠依据，
   建议联系相关职能部门确认"，不得猜测、不得用常识补全。
3. 每条回答必须标注来源。

【输出格式】
先给结论，再给依据，最后列来源。
```

4. 打开 **「引用和归属」**，让回答显示来源卡片 —— 这是企业级产品的底线
5. **「发布」** → 拿到分享链接 / 嵌入代码

### 3.4 顺手做的两件事

- 截 3 张图：**知识库配置页 / 问答效果（带来源卡片）/ 命中不了的诚实拒答** → 放进 GitHub README
- 录 2 分钟视频，重点演示「问一个文档里没有的问题，它老实说不知道」

## 4. 路径 B：Docker 本地部署（想要完整产品形态时再做）

### 4.1 前置

1. 安装 **Docker Desktop for Windows**（官网下载，需开启 WSL2，**要求 ≥ 8GB 内存**）
2. 安装后重启，确认命令行可用：

```powershell
docker --version
docker compose version
```

### 4.2 部署

> Dify 官方仓库会持续更新，这里给的是通用步骤。**执行前先看官方仓库当前 README，以它为准。**

```powershell
git clone https://github.com/langgenius/dify.git
cd dify\docker
copy .env.example .env
docker compose up -d
```

首启动会拉镜像，**5~15 分钟**（取决于网速）。完成后：

```powershell
docker compose ps          # 看所有容器是否 healthy
```

浏览器打开 `http://localhost/install`，设置管理员账号，然后按 **第 3.2 节的参数**配置知识库。

### 4.3 常用运维

```powershell
docker compose logs -f api     # 看日志
docker compose stop            # 停止
docker compose down            # 销毁（数据卷保留）
```

### 4.4 装不动怎么办

如果 Docker 安装失败或内存不够，**别硬刚**：

- 用 **路径 A（云端）** 拿界面
- 用 **路径 C（Python）** 拿数据和评测
- 在文档里诚实写一句「本地部署受限于开发机内存，改用云端验证」—— 这是工程判断，不是减分项

## 6. 这个原型对简历的价值

```
❌ 只写文档           → "又一个纸上谈兵的学生"
✅ 代码 + 评测集 + 报告 → "她真的跑过数据，而且知道哪些数字不能信"
```

具体能让你说出这些话（面试原话级）：

- 「我的 V0 基线在 100 条评测集上正确率 86.2%，但我更关注幻觉率 10%——因为不设阈值时正确率有 93.8%，代价是 100% 的幻觉率，那是不能上线的。」
- 「我试过 jieba 分词，结果正确率从 86.2% 掉到 68.8%。所以我不迷信工具，只信评测集。」
- 「剩下的 10% 幻觉，纯调阈值已经无解——那几道题的关键词分数比可答题还高，必须上语义检索。这就是我 V1 的第一优先级。」
- 「我还踩过一个坑：文档里写『提前 1 天』、我评测要点写『提前1天』，导致所有指标虚低一半。测出来的其实是排版格式，不是产品能力。」

**这四句话里，有数据、有取舍、有归因、有失败复盘。** 这就是 3 年经验和应届生的差别。
